# 页面结构

延续「数字是主角、表要密、筛选要吸顶」。下面是当前实现，不是占位线框。

## 概览 `/`

```
┌侧栏────────┬ 吸顶筛选：昨日|近7日|本周|本月  日期  代理商锁  子户  网络  单位 ┐
│ 翊 翊行财务 │ 概览                         单位 元 · 区间 · fixtures · 只读 │
│ 账本        │ ┌充值合计 28–32px┐ ┌消耗┐ ┌收入┐ ┌期末余额┐                  │
│ ▌概览       │ └点进充值流水────┘ └───┘ └───┘ └────────┘                  │
│  充值流水   │ ┌日差额┐ ┌未匹配┐ ┌部分匹配┐                                  │
│  收入流水   │ ├按日充值/消耗柱─────────────┬ 收入构成 穿山甲/优量汇 ┤        │
│  对账汇总   │ ├子户 充值·消耗·期末余额─────┬ 未匹配队列（点进对账）─┤        │
│  报表(二期) │ └毛利草稿（折叠，标非关账）──────────────────────────────────┘
│  深色       │
└────────────┘
```

移动：底栏替代侧栏。筛选收进「筛选」。KPI 两列。未匹配队列在子户表下面。

## 充值 `/recharges`

页头下四格：区间充值（主指标）、笔数、扣回、区间消耗。其下按日柱。资金类型切换表：充值流水 / 消耗 / 余额快照。表头吸顶，合计吸底。已冲正删除线。`MANUAL-` 标「人工」。扣回金额带 `−`。

## 收入 `/revenues`

净收入为主指标，旁边毛收、平台费、预估笔数。一条网络占比。表列含结算状态 chip。说明条写明默认含预估，关账看结算。

## 对账 `/reconcile`

默认近 7 日、状态未匹配。四个 Tab 上带该区未匹配计数。本区 KPI：未匹配、部分匹配、Σ|delta|（主数字）、匹配率。行左侧色条：红未匹配 / 琥珀部分 / 绿已匹配。点行打开右侧抽屉（移动为全屏 Sheet）：左右金额、构成、证据。无提交按钮。跨源 Tab 标「仅观察 · 非关账」。

## 状态

| 态 | 表现 |
|---|---|
| 加载 | 筛选仍在；KPI 与表为骨架。fixtures 路径的静态 HTML 直接有数字 |
| 空 | 说明原因（日期无数据 / 分区无结果 / 全部已匹配） |
| 错误 | 红卡 + `request_id` + 「重新加载」。`?mock=error` 可看 |
| 成功 | 页头写数据源 `fixtures` 或 `mario /api/v1` |

## 动线

概览主指标链到对应流水并带上当前 `quick`。未匹配队列进入对账，带上 `status=unmatched` 与该行 `tab`。侧栏跳转只保留 URL 里已经写下的 `quick/from/to/subs/unit/mock`，因此从默认概览进对账仍是对账自己的「近 7 日 + 未匹配」。
